RL OpenKBP — Full Pipeline · V5 sequential multi-step MDP (one episode = one 35-fraction course) · live GAE · potential-based shaping + terminal objective · per-fraction dose cap · NNLS warm-start before PPO · OAR curriculum · Flask web UI · plain-english walkthrough using the same vocabulary as the lectures

What this project does. It trains a reinforcement-learning (RL) agent to plan a radiotherapy treatment for head & neck cancer patients. Treatment is split into 35 daily sessions ("fractions"). For each session the agent decides how strongly to fire 9 radiation beams from different angles around the patient. The goal is the classic clinical trade-off: deliver enough dose to kill the tumour while sparing the healthy organs next to it.

How it is framed as an RL problem (course vocabulary). We model the problem as a finite-horizon Markov Decision Process $(S, A, p, r, \gamma)$. In V5 each episode is the whole 35-fraction patient course: DoseEnv.step returns done = True only on the final fraction. The agent state $S_t$ is the Markovian summary the network sees (CT + structure masks + cumulative dose so far + remaining gap + $t/35$), the action $A_t$ is the 2,304 beamlet intensities for this fraction, and $p$ is deterministic (the DIM multiplies the action to get dose). Because the horizon is real, $\gamma = 0.99$ and $\lambda_{\text{GAE}} = 0.95$ are LIVE — PPO runs genuine Generalised Advantage Estimation and the critic bootstraps return-to-go across the remaining fractions, doing real temporal credit assignment.

How the reward works. The dense per-fraction signal is potential-based shaping (Ng et al. 1999): $r_t = \gamma\,\Phi(S_{t+1}) - \Phi(S_t)$, where the potential $\Phi$ rewards a small remaining PTV gap and an under-budget OAR dose. Shaping is policy-invariant — it accelerates learning without changing the optimal policy. The real objective is a terminal reward paid out only on the last fraction: $\lambda_{\text{ptv}}\cdot\text{coverage} - \text{terminal\_dvh\_weight}\cdot\text{dvh\_score}$. A physical per-fraction dose cap ($\text{max\_fraction\_dose} = 3$ Gy/voxel) forces the agent to spread dose over the course instead of dumping it in one shot.

Two-stage learning. Before any PPO begins we solve a per-patient non-negative least-squares (NNLS) oracle $a^\ast = \arg\min_{a \geq 0} \lVert \sqrt{W}\,(\text{DIM}\,a - d_\text{gt}/n)\rVert_2^2$ and supervised-pretrain the actor head against $\operatorname{inv\_softplus}(a^\ast)$. This breaks the symmetry of the uniform-init policy. PPO then takes the warm-started policy, starts it with a wide exploration band (log-std init 0.0 ⇒ $\sigma = 1$) so it can break away from that one-shot baseline, and adapts it to maximise the whole-course objective. An OAR-penalty curriculum ramps $\lambda_{\text{oar}}$ from 10 % to full over the first 600 patients so the agent commits to coverage before it is heavily penalised for incidental OAR dose.

A Flask web UI. app.py serves a JSON API (health, config, patient list, per-patient deterministic simulation, end-of-treatment summary) that a browser front-end consumes to visualise beam heatmaps, cumulative organ doses and PTV/OAR outcomes per fraction — see Phase 4.

Coverage status. An earlier release had a bug in the DIM voxel downsampler that left ~25 % of PTV voxels unreachable, capping full-mask D95_PTV* at 0 Gy. The fixed downsampler (Step 3) does source-side aggregation with a target-side nearest-source fallback, so every target voxel now has at least one DIM contributor; PTV reachability is 99.7–100 % across all 206 patients and full-mask D95 matches D95r within rounding.

Glossary — the words you'll keep seeing

MDPmarkov decision process
The mathematical framing for the whole project (Lecture 3). An MDP is the tuple $(S, A, p, r, \gamma)$: a set of states, a set of actions, a transition / reward model $p(r, s' \mid s, a)$, and a discount factor $\gamma \in [0,1]$. Here $S$ is "the patient and what we've already done", $A$ is "the 2,304 beamlet intensities to fire this fraction", and $p$ is fully deterministic (the DIM multiplies the action to get the dose). In V5 the horizon is the real 35-fraction course, so $\gamma$ genuinely discounts future fractions. We assume the Markov property: once the state is known, the history can be thrown away — which is why we explicitly stuff cumulative dose and the remaining gap into the state.
agent / environment state$S_t$ vs the world
Lecture 1's distinction. The environment state is the patient's true biology — hidden and huge. The agent state $S_t$ is the compact, Markovian summary the network actually sees. In our project that's 12 channels of $64^3$ (CT + 8 masks + cum dose + remaining gap + beam paths) plus the scalar $t/35$. Everything the policy/critic decides flows from this $S_t$. Because it carries the whole history (cumulative dose), a plain feed-forward policy is sufficient — no recurrence needed.
reward $R_{t+1}$ & return $G_t$scalar feedback + cumulative
The reward hypothesis (Lecture 1): any goal can be expressed as maximisation of a scalar reward. After every fraction the environment emits one number $R_{t+1}$ — the potential-based shaping increment, plus a terminal grade on the last fraction. The return is the discounted cumulative reward $G_t = R_{t+1} + \gamma R_{t+2} + \ldots$ that the value function tries to estimate. The return is real here ($\gamma = 0.99$ over the 35-step horizon), so the value function genuinely estimates return-to-go.
policy $\pi$ & value $v_\pi$actor & critic
A policy $\pi(a \mid s)$ maps state to a distribution over actions — in our code, the actor head that outputs a Gaussian over 2,304 raw beamlet weights (then softplus). The value function $v_\pi(s) = \mathbb{E}[G_t \mid S_t = s, \pi]$ is the expected return from $s$ under $\pi$ — in our code, the critic head (its own 3-layer MLP). The advantage $A_\pi(s, a) = q_\pi(s, a) - v_\pi(s)$ is what PPO's gradient is weighted by; we estimate it with GAE.
episodefinite-horizon trajectory
A sequence of $(S, A, R)$ tuples that ends when done = True. An episode is the full 35-fraction patient course — done flips True only on fraction 35, so the trajectory is a genuine 35-step horizon and the value function must propagate the terminal grade backward.
potential-based shaping$\gamma\Phi(s')-\Phi(s)$
The dense per-fraction reward in V5 (Ng, Harada & Russell 1999). We define a potential $\Phi(\text{state})$ that is higher for "better" cumulative-dose states, then reward the agent the change in discounted potential each step: $r_t = \gamma\,\Phi(S_{t+1}) - \Phi(S_t)$. The key theorem: adding such a term does not change the optimal policy of the underlying objective — it only reshapes where the reward arrives in time, giving PPO a gradient on every fraction instead of a single sparse terminal grade. Here $\Phi = -\lambda_\phi\cdot\text{ptv\_gap\_fraction} - \lambda_{\text{oar}}\cdot\text{oar\_overshoot\_fraction}$, both computed on the cumulative dose.
terminal objectivethe real grade
The whole-course reward emitted only on fraction 35: $\lambda_{\text{ptv}}\cdot\overline{\text{coverage}} - \text{terminal\_dvh\_weight}\cdot\text{dvh\_score}$, where $\overline{\text{coverage}}$ is the mean over PTVs of the fraction of voxels at or above prescription, and dvh_score (lower = better) measures how close the plan's DVH is to the clinical one. This is what $\gamma$ propagates backward through GAE — the shaping just speeds the journey there.
OARorgans at risk
Healthy organs near the tumour that we want to protect. In this project there are exactly five: brainstem, spinal cord, mandible (jaw bone), left parotid (saliva gland) and right parotid. Each has a "safe limit" in Gy that we don't want the dose to cross.
PTVplanning target volume
The tumour region the plan must "cover" with a prescribed dose. There are three classes — PTV70 needs 70 Gy, PTV63 needs 63 Gy, PTV56 needs 56 Gy — spread across the 35 sessions. Most head & neck patients have all three nested volumes (PTV70 is the gross tumour, PTV63 is high-risk margin, PTV56 is elective nodes).
Gygray (the unit of dose)
1 gray = 1 joule of radiation absorbed per kilogram of tissue. Tumours need 56–70 Gy total; spinal cord must stay under 45 Gy. That's why every number in this project is in Gy.
fractionone treatment session
One day's session. There are 35 of them in a full course. Each session adds a small amount of dose (~2 Gy/session for PTV70) so the body has time to recover between sessions. The per-fraction dose cap (3 Gy/voxel) makes spreading dose across these 35 sessions mandatory.
beam & beamletradiation pencils
A "beam" comes from one angle around the patient (we use 9 angles spaced 40° apart). Each beam is split into a grid of tiny pencil beams called "beamlets" (16 × 16 = 256 per beam). The agent controls each beamlet's intensity independently — that's how you sculpt the dose around an organ.
DIMdose-influence matrix
A pre-computed table that says: "if I fire beamlet j at intensity 1, voxel i receives X Gy." It has 262,144 rows (one per voxel) and 2,304 columns (one per beamlet). Once it's built, computing a dose plan is just one (sparse) matrix multiplication — milliseconds instead of minutes.
CT & HUthe anatomy image
CT is a 3D X-ray scan of the patient. Brightness in standard radiology is measured in Hounsfield Units (HU): air = −1000, water = 0, bone ≈ +1000. OpenKBP stores CT as HU + 1000 (a non-negative integer), so the CSVs you'll see contain values from ~0 (air) up to ~4000 (dense bone / metal). Before feeding it to the network we subtract 1000, clip to a fixed window and rescale into [−1, 1] so it sits on the same scale as the binary masks.
voxel3D pixel
A 3D pixel. Each voxel has a position in the patient's body and one number per layer (CT brightness, dose, mask value, …). The grid in this project is 64 × 64 × 64 = 262,144 voxels.
D95tumour coverage
The dose received by at least 95 % of the tumour. The clinical gold standard: if D95 ≥ prescription, the tumour is well covered. If D95 falls below, the coldest 5 % of the tumour may not get enough dose.
DVH & DVH scoredose-volume histogram
A DVH is a curve summarising the whole dose distribution in one shape. Our DVH score (used to pick best.pt and to report quality) is a proxy: the mean over present structures of $|\Delta D95| + |\Delta D_\text{mean}|$ versus the clinical ground-truth dose. Lower is better.
MAEmean absolute error
Average of |predicted dose − clinical dose|, computed only over voxels inside the body. Tells you how close the agent's plan is to the human dosimetrist's plan on average.
PPOproximal policy optimisation
The on-policy policy-gradient algorithm doing the actual learning. It updates a stochastic policy $\pi_\theta(a\mid s)$ to maximise expected return, but each update is clipped to a trust region (probability ratio kept in $[1-\varepsilon, 1+\varepsilon]$ with $\varepsilon = 0.2$) so the new policy never moves too far from the old one in a single step.

When does it update in V5? We buffer 8 whole-course trajectories (batch_n_patients), i.e. $8 \times 35 = 280$ transitions, then run a single PPO update over that batch with advantages normalised across all of it. So "8 patients = 1 PPO update".
GAEgeneralised advantage estimation
PPO's estimator of the advantage $A_t = q_\pi(s,a) - v_\pi(s)$. GAE blends every $k$-step TD residual $\delta_t = R_{t+1} + \gamma\,v(S_{t+1}) - v(S_t)$ with an exponentially decaying weight $\lambda$:
A_t = δ_t + (γλ)·δ_{t+1} + (γλ)²·δ_{t+2} + …

Here it runs for real. Because only the last fraction has done = True, the bootstrap $\gamma\,v(S_{t+1})$ is live for fractions 1–34, so the critic genuinely carries the terminal grade back across the course. $\gamma = 0.99$ and $\lambda = 0.95$ do drive credit assignment.
per-fraction dose cap$\text{max\_fraction\_dose}$
A physical clip applied to each fraction's dose volume: fraction_dose = min(fraction_dose, 3 Gy) per voxel. Without it the agent could dump the entire course in one fraction; the cap forces the allocation to be genuinely sequential, so the 35-step MDP framing is meaningful and the cumulative dose builds up gradually.
OAR curriculum$\lambda_{\text{oar}}$ ramp
For the first lambda_oar_ramp_episodes = 600 patients, the effective OAR penalty weight ramps linearly from $0.10\times$ the target up to the full $\lambda_{\text{oar}}$. Early on the PTV reward dominates so the agent learns to actually deliver dose; without the ramp PPO tends to collapse to a near-zero-action policy because the marginal OAR penalty exceeds the marginal PTV gain at initialisation.
softplusthe "never negative" function
softplus(x) = log(1 + eˣ). Always ≥ 0, can get very close to zero. We apply it to the network's raw output because you cannot deliver negative radiation, but we still want the agent to be able to "turn a beamlet almost off".
NNLS warm-startper-patient oracle plan $a^\ast$
Before PPO starts, we solve a weighted non-negative least-squares problem per patient: $a^\ast = \arg\min_{a \geq 0}\,\lVert\sqrt{W}(\text{DIM}\,a - d_\text{gt}/n_\text{fractions})\rVert^2$ via FISTA. $W$ upweights PTV voxels (×50) and OAR voxels (×5) so PTV coverage dominates the fit. Result: a per-beamlet plan that, if repeated identically every fraction, approximates the clinician's full dose. We cache $a^\ast$ as warmstart_action.npy and use it as a supervised target for the actor head (Step 4a).
reachabilityDIM coverage check
A voxel $v$ is reachable if at least one beamlet has a non-zero DIM entry into it (row-sum > 0). The original downsampler left ~25 % of PTV voxels unreachable whenever pyRadPlan's native dose grid was coarser than 64 in any axis. The fix in _downsample_matrix uses source-side aggregation plus a target-side nearest-source fallback so every target voxel has at least one DIM contributor; current PTV reachability is 99.7–100 % across all 206 patients. evaluate.py still reports D95r and %reach so any future regression shows up immediately.
splittrain / validation / test
Three groups of patients. Train is what the agent learns from. Validation is held out so we can compare runs and pick the best checkpoint (V5 uses its DVH score to save best.pt). Test is touched once at the very end for the final, unbiased number.

Step 1 · Clean, resample, and stack into 3D arrays
load_patient → SimpleITK resample to 64³ → CT → [−1, 1] → ray-cast beam paths

This step turns the sparse CSVs into clean, ready-to-use 3D arrays.

For every patient we (1) rebuild each organ mask and dose volume back into a full 3D grid, (2) resample everything to a fixed 64 × 64 × 64 cube using the real millimetre spacing so patients of different scan depths all end up the same shape, (3) subtract 1000 from the CT (OpenKBP stores it as HU + 1000) to recover true Hounsfield units, then clip to [−1000, +1000] HU and divide by 1000 → [−1, 1], and (4) pre-draw a simple "beam-path map" — for each of the 9 gantry angles (spaced 40° apart) we cast one ray through the iso-centre and extrude the touched (x, y) voxels along the full z range.

If an organ file is missing for a patient (not every patient has every organ), it becomes an all-zero mask channel and the reward and metrics layers know to skip it — nothing crashes.

Step 3 · Build the Dose Influence Matrix (DIM) slow, but only once
pyRadPlan(SVDPB) · 9 gantry angles 40° apart · 16 × 16 beamlets per beam · → dose_influence_matrix.npz, sparse CSR of shape (262144 × 2304)

pyRadPlan is an open-source radiotherapy physics library. We hand it the patient's CT, the organ outlines, and our beam setup (9 angles, each split into a 16 × 16 grid of beamlets = 256 beamlets/beam = 2,304 beamlets total). It then simulates how X-rays travel through the body — taking into account that bone, muscle and air absorb differently.

The result is the Dose Influence Matrix (DIM): a big table with one row per voxel (262,144 rows) and one column per beamlet (2,304 columns). Each cell answers: "how many Gy does this beamlet deposit in this voxel at intensity 1?" It is stored as a sparse CSR matrix (dose_influence_matrix.npz); legacy dim.npz / dim.npy files still load for back-compat.

This simulation is slow (5–10 min per patient), but it only runs once per patient — the body doesn't change between sessions. The huge payoff: during training, computing the dose for any choice of beam intensities becomes one fast matrix multiplication: dose = DIM · intensities.

Voxel downsampler (now fixed). pyRadPlan returns the DIM on its own dose grid (typical: 47×100×100, often coarser than 64 in z) and we resample it to 64³ with a sparse mean-pool matrix. The original implementation routed every source voxel into floor(s·grid/N), which for axes with N<grid left whole rows of target voxels unmapped — leaving ~25 % of PTV voxels with all-zero DIM rows and pinning full-mask D95 to 0 Gy. The fix is two-pass: (1) every source voxel aggregates into its target via the nearest-centre rule floor((s+0.5)·grid/N); (2) any target voxel left unfilled gets a single nearest-source contribution floor((t+0.5)·N/grid). Row-totals are then normalised. After the fix every target voxel is covered and PTV reachability is 99.7–100 % on all 206 patients.

Step 3b · Per-patient NNLS warm-start oracle plan a*
weighted FISTA-NNLS · target = $d_\text{gt}/n_\text{fractions}$ · weights: PTV ×50, OAR ×5, body ×1 · → warmstart_action.npy of shape (2304,)

This step pre-computes a high-quality beamlet plan per patient that the actor head will imitate before PPO begins. Without it, the actor head starts from a uniform initialisation and PPO cannot move it in any reasonable number of episodes (the policy stays frozen at softplus(-1) ≈ 0.31 per beamlet).

We frame it as weighted non-negative least-squares:

$a^\ast \;=\; \arg\min_{a \geq 0}\;\lVert \sqrt{W}\,(\text{DIM}\,a \;-\; d_\text{gt}/n_\text{fractions}) \rVert_2^2$

  • Target $d_\text{gt}/n_\text{fractions}$ — the per-fraction "fair share" of the clinician's total dose. If the agent could repeat $a^\ast$ every fraction, the cumulative would approximate dose_gt.
  • Per-voxel weights $W$ — body voxels weight 1, OAR voxels weight 5, PTV voxels weight 50. Without weighting, body voxels (~95 % of the volume) drown the fit and PTVs are under-dosed.
  • Solver — FISTA (accelerated projected gradient) with a non-negativity projection each step and Nesterov momentum; ~400 iterations per patient, ~10 s on CPU.

Cache: one warmstart_action.npy per patient. Typical $a^\ast$ is sparse — only a fraction of the 2304 beamlets are meaningfully active — which is exactly the kind of structured plan that beats the uniform-init baseline immediately. (Exact weights and iteration count live in scripts/compute_warmstart_actions.py.)

see scripts/compute_warmstart_actions.py · solver fista_nnls_weighted
Phase 2 — Training loop (one episode = one 35-fraction course · 8 courses per PPO update)
Step 4a · Supervised actor pretraining on $a^\ast$ runs once, before PPO
target = $\operatorname{inv\_softplus}(a^\ast / \text{ACTION\_SCALE})$ · loss = MSE on actor_mu output · 30 epochs · minibatch 4 · Adam lr 3e-4 · updates encoder + actor trunk + actor_mu

Before PPO starts, we load each training patient's $a^\ast$ from Step 3b, build the fraction-0 state, and fit the actor head so that its deterministic output reproduces $a^\ast$. Concretely we regress actor_mu(features(state, t/35=0)) against $\operatorname{inv\_softplus}(a^\ast) = \log(\exp(a^\ast) - 1)$, floored at $-8$ so zero-beamlets don't blow up to $-\infty$.

Why pretrain $\mu$ instead of the full distribution? We want to keep the on-policy exploration noise (log_std) intact for PPO — we only need to break the per-beamlet symmetry of the uniform initialisation. The critic and log_std are deliberately left at their init values; PPO learns them from scratch. The state stack is kept on the host and only minibatches are shipped to the GPU, so the ~200-patient warm-start fits in normal RAM.

Why 30 epochs? In the sequential setup PPO must start near a feasible plan rather than near zero — more supervised epochs is the main lever for fixing PTV underdose at the start of training, before the OAR curriculum begins to bite.

We save the post-pretrain weights to runs/warmstart.pt so you can evaluate the imitation policy alone and compare it to the post-PPO policy.

Step 4 · Start a new patient course env.reset() = one episode
pick a train patient → load .npy + dose_influence_matrix.npz → cumulative_dose = zeros(64³) → fraction_index = 0

A patient course means treating one patient through all 35 fractions — and in V5 that whole course is one episode. env.reset() is called once per patient: we pick a random patient from the train split, load their cached arrays and DIM into memory, zero out the running cumulative dose volume, and reset the session counter t = 0.

Each step() inside the course advances one fraction. The environment's internal state — cumulative_dose, fraction_index, self._patient — persists across the 35 steps, and done is returned False until fraction 35, where it equals info["patient_done"]. The training loop watches that flag to know when to reset to the next patient.

Step 5 · Build the state — what the agent sees
12 channels of 64 × 64 × 64 + a scalar t/35

Before deciding anything, the agent looks at a stack of 12 3D layers, each covering the whole patient:

ch 0CT scan (anatomy)The patient's tissue map in [−1, 1] — lets the agent see where bone, soft tissue and air are so it knows what each beam will be passing through.
ch 1–3PTV70 · PTV63 · PTV56 masksThree binary 0/1 volumes pinpointing exactly where the three tumour targets sit and what dose level each one is asking for.
ch 4–8Brainstem · SpinalCord · Mandible · L/R Parotid masksFive binary masks marking the organs the agent must protect, each on its own channel so the network can learn organ-specific avoidance behaviour.
ch 9cumulative dose so far ÷ 70A running tally of the dose already delivered in earlier sessions — this is the agent's memory of "what have I done up to now". It is what makes the state Markov despite a feed-forward policy.
ch 10remaining tumour dose ("the gap") ÷ 70Per-voxel difference between each PTV's prescription and the dose accumulated so far, clipped ≥ 0 — a live to-do map showing which tumour regions still need more radiation.
ch 11beam-path mapA pre-drawn sketch of which voxels each of the 9 gantry angles passes through, so the agent understands the geometric reach of every beam direction. All 9 angles are merged into this one volume — it does not distinguish which beam touched which voxel, only "is this voxel inside some beam path."

Why divide by 70? Networks learn best when all inputs sit in a similar small range. Mixing huge numbers (50 Gy) with small ones (binary masks of 0/1) confuses them.

A single extra number — t/35, "what fraction of the course is done" — is not stacked as a channel. It's appended later, after the CNN compresses the 12 layers.

Step 6 · 3D-CNN encoder — squeeze the volume into 128 numbers
12 × 64³ → Conv3d × 4 (stride 2) → 4³ → AdaptiveAvgPool → 128 → +1 scalar t/35 → 129 features

The 12 × 64³ state has ~3 million numbers — far too many for the decision-making layer. A 3D Convolutional Neural Network (CNN) slides small 3D filters over the whole volume, looking for meaningful local patterns (e.g. "tumour voxel right next to spinal cord that's already nearly at its limit").

Four convolution layers halve the volume each time (64 → 32 → 16 → 8 → 4) while growing the number of "feature channels" (12 → 16 → 32 → 64 → 128). An adaptive average-pool collapses the 4³ × 128 feature volume into 128 numbers, and a small linear layer projects them into the final 128-number summary vector.

Finally we tack on the single scalar t/35, giving a 129-number feature vector. Both the actor (which picks an action) and the critic (which scores the state) read from this same vector through their own trunks.

Step 7 · Actor head — the agent picks its action
features (129) → Linear 256 + ReLU → Linear 256 + ReLU → mu (2,304) ; std = clamp(log_std, [−5, +2]).exp(); raw ~ Normal(mu, std); action = softplus(raw) · ACTION_SCALE

This is the heart of the RL agent. The 129-number feature vector from Step 6 is fed into the actor trunk: two fully-connected layers of width 256, each followed by ReLU. The output goes through one more linear layer — actor_mu — producing a vector of length 2,304, one number per beamlet. That vector is mu: the centre of the Gaussian the agent samples from for each beamlet. It lives in raw pre-softplus space and can be negative; only after the sample passes through softplus does it become the non-negative intensity vector multiplied by the DIM in Step 8.

Initialisation. The actor_mu weights use orthogonal init with gain 0.01 and the bias is initialised to ACTOR_MU_BIAS_INIT = -1.0, so a fresh untrained policy outputs $\mu \approx -1$ for every beamlet (deterministic action $\operatorname{softplus}(-1) \approx 0.31$ uniformly). That uniform-init policy is a pathological local minimum, which is why Step 4a's supervised warm-start replaces this uniform $\mu$ with per-beamlet $\operatorname{inv\_softplus}(a^\ast)$ before PPO ever runs.

Exploration band — wide on purpose. The standard deviation is a state-independent, learnable parameter log_std, one value per beamlet. In V5 it is initialised from the config to actor_log_std_init = 0.0 (so initial $\sigma = e^0 = 1.0$) and clamped each forward pass to $[-5, +2]$ (so $\sigma \le e^2 \approx 7.4$). Why so wide: because mu is warm-started onto the static one-shot NNLS plan, a narrow $\sigma$ would pin the policy to that baseline and stop it discovering genuinely multi-step strategy. Starting wide lets PPO deviate from the warm-start and explore how to sequence dose across fractions.

Sample vs. mean — train vs. eval. The agent's act() method has a deterministic flag:

  • Training (deterministic=False): raw = dist.sample() — one random draw from Normal(mu, std) per beamlet. This lets the agent explore.
  • Evaluation / the web UI (deterministic=True): raw = dist.mean (just mu). No randomness — running the same patient twice produces the exact same plan, mandatory for clinical reproducibility.

Log-probability for PPO. The actor also returns logp = dist.log_prob(raw).sum(-1) — the total log-probability of that sample under the current policy. PPO stores this old log-prob and later compares it to the new one after an update, forming the clipped probability ratio. PPO computes log_prob on the raw sample (not the softplus output); this works because softplus is monotonic.

From raw sample to physical intensities. A Normal is unbounded, but you can't deliver negative radiation. So we run raw through softplus and scale by ACTION_SCALE = 1.0: a smooth map to a strictly positive value that can still get arbitrarily close to zero. The result is the action — the 2,304-long vector of non-negative intensities shipped to Step 8.

see ActorCritic (forward + to_action) and PPO.act · n_beamlets = 9 · 16 · 16 = 2,304 · ACTOR_MU_BIAS_INIT = −1.0 · actor_log_std_init = 0.0 · log_std clamp = [−5, +2] · ACTION_SCALE = 1.0

Step 8 · Apply the DIM — turn intensities into dose + per-fraction cap
fraction_dose = DIM · intensities ; mask outside body ; clip to max_fraction_dose = 3 Gy ; cumulative_dose += fraction_dose

Now we cash in the DIM we built earlier. The 2,304-long intensity vector is multiplied by the (sparse) DIM, instantly giving the dose (in Gy) that each of the 262,144 voxels would receive in this single session.

We then multiply by the possible-dose mask — OpenKBP's region where dose is allowed to be evaluated — so spillover into empty air is zeroed out.

Per-fraction dose cap. Each voxel's fraction dose is then clipped to max_fraction_dose = 3 Gy. This is what forces the agent to spread dose across the 35 fractions instead of dumping it all at once — without it, the sequential MDP would degenerate back into a one-shot allocation. Anything the agent tries to push above the cap is wasted, and it learns not to.

The capped fraction dose is added to the running cumulative dose volume. That cumulative dose is what the next state shows the agent through channels 9 (delivered) and 10 (still missing) — so the agent always knows where it stands.

see DoseEnv.step · no live pyRadPlan call here — just one sparse matrix multiply + clip
↓
Step 9 · Reward signal potential-based shaping + terminal objective
$R_{t+1} = \gamma\,\Phi(\text{cum}_{\text{after}}) - \Phi(\text{cum}_{\text{before}})\;\;[+\;\text{terminal grade if fraction 35}]$
The agent is never told "the correct beam intensities" — those don't exist in the data. In V5 the learning signal has two parts: a dense potential-based shaping term on every fraction, plus a terminal whole-course grade on fraction 35. The shaping is policy-invariant (it can't change the optimal plan, only speed learning toward it); the terminal grade is the real objective that $\gamma$ carries backward through GAE.

Note: a per-fraction PTV reward and OAR penalty are also computed every step and returned in info as diagnostics (so the training log carries ptv / oar columns), but they do not feed the reward — the shaping and terminal terms above are the actual signal.
  • 1 · Dense shaping — change in potential each fractionfractions 1–35 · policy-invariant
    ptv_gap_fraction = mean over PTV voxels of clip(Rx − cumulative_dose, 0) / Rx
    Unmet PTV fraction, in [0, 1]. 0 means every PTV voxel is already at or above prescription; 1 means nothing delivered. Computed on the cumulative dose so it summarises the whole history (Markov).
    oar_overshoot_fraction = Σ_organs organ_weight · max(0, mean_dose − tol) / tol
    Weighted OAR overshoot vs the FULL-course tolerance. 0 while every organ's cumulative mean dose stays under budget; grows once an organ exceeds its whole-course tolerance. Scaled by the per-organ weights (parotids 1.6, serials 0.5–0.6).
    Φ(cumulative_dose) = − λ_phi · ptv_gap_fraction − λ_oar · oar_overshoot_fraction
    The potential. Higher (closer to 0) is a better state: small PTV gap and under-budget OARs both raise Φ. λ_phi = 1.0; λ_oar is the curriculum-ramped value (see Step 10 / training loop).
    shaping_reward = γ · Φ(cum_after) − Φ(cum_before)
    Potential-based shaping (Ng et al. 1999). Rewarding the discounted increase in potential gives PPO a gradient every fraction while provably leaving the optimal policy of the terminal objective unchanged. γ = 0.99.
    Intuition: each fraction the agent is paid for how much closer it moved the cumulative plan toward "all PTV gap closed, no OAR over budget", discounted by $\gamma$. Because it is a difference of potentials, the contributions telescope over the course — the total shaping reward depends only on the start and end states, so it cannot bias the agent toward a worse final plan.
    Why shape at all? The real objective only arrives on fraction 35. Without shaping, fractions 1–34 would carry almost no gradient and PPO would learn glacially. Shaping front-loads a dense, unbiased signal.
  • 2 · Terminal objective — the whole-course gradefraction 35 only
    coverage_mean = mean over present PTVs of fraction of voxels with cumulative_dose ≥ Rx
    PTV coverage. For each tumour class, the share of its voxels that reached prescription; averaged across the PTVs the patient actually has. This is the headline "did we treat the tumour" number.
    dvh_score = mean over present structures of |ΔD95| + |ΔDmean| vs ground-truth dose
    Plan-quality penalty (lower better). How far the finished plan's DVH summary sits from the clinician's. Computed by metrics.dvh_score on the final cumulative dose.
    terminal_reward = λ_ptv · coverage_mean − terminal_dvh_weight · dvh_score
    Added to fraction 35's reward. λ_ptv = 3.5, terminal_dvh_weight = 0.1. This is the only term GAE has to carry backward — every earlier fraction's value estimate exists to predict it.
    The terminal grade is what makes this a real sequential-decision problem: the agent must arrange 35 capped fractions so that the final cumulative dose both covers the tumour and matches a clinically sensible DVH. The critic learns to predict this grade from any mid-course state, and $\gamma$ discounts it back so early fractions are credited for setting up a good ending.
    Why grade on coverage + DVH? Because the objective we actually care about is a property of the finished plan, not of any single fraction. The sequential framing lets us optimise that directly, with the dense shaping providing per-fraction guidance toward it.
R_{t+1} = γ · Φ(cumulative_after) − Φ(cumulative_before)
       + [ λ_ptv · coverage_mean − terminal_dvh_weight · dvh_score ]  if fraction_index == 35

Φ = − λ_phi · ptv_gap_fraction − λ_oar · oar_overshoot_fraction
λ_phi = 1.0 · λ_oar = 0.6 (ramped) · λ_ptv = 3.5 · terminal_dvh_weight = 0.1 · γ = 0.99  (in configs/default.yaml)
The shaping pulls the cumulative plan toward "tumour covered, organs spared" every fraction; the terminal grade is the actual exam at the end. Because the shaping is a potential difference, the two are consistent — the dense signal never rewards anything that would hurt the final grade.

↓  at the end of all 35 fractions we have one full Rollout (35 transitions of (state, action, reward, value, logp, done)); 8 such rollouts are buffered before a PPO update
Step 10 · PPO update — one update per 8 patients src/agents/ppo.py
8 × 35 = 280 transitions · real GAE (γ = 0.99, λ = 0.95, last_value = 0) · advantages normalised across the batch · clip ε = 0.2 · 6 epochs × minibatch 64 · lr 1.5e-4 · grad clip 0.5 · rewards & values clipped to [−50, +50] · NaN-skip

The training loop buffers batch_n_patients = 8 whole-course rollouts, then runs a single PPO update over all 280 transitions.

(0) Defensive clipping. Both rewards and values are clipped to $[-50, +50]$ before any maths. A single very bad fraction during early exploration can otherwise produce a huge reward that destabilises the value target and advantage normalisation. Anything non-finite after clipping causes the whole update to be skipped — better to lose one batch's gradient than to poison Adam's moments with NaNs.

(a) Real GAE. Each trajectory gets its own GAE pass: $\delta_t = R_{t+1} + \gamma\,V(S_{t+1})\,(1-\text{done}_t) - V(S_t)$, accumulated backward with weight $\gamma\lambda$. Because done is True only on fraction 35, the bootstrap $\gamma V(S_{t+1})$ is live for fractions 1–34 — the critic genuinely carries the terminal grade back across the course (last_value = 0 is the correct terminal bootstrap). Advantages from all 8 trajectories are concatenated and normalised to mean 0 / std 1 across the whole batch (lower variance than per-trajectory normalisation with only 35 steps each).

(b) Clipped policy update. Standard PPO surrogate: probability ratio $\rho_t = \pi_{\text{new}}/\pi_{\text{old}}$ clipped to $[0.8, 1.2]$, actor loss $-\mathbb{E}[\min(\rho_t A_t, \text{clip}(\rho_t)A_t)]$. The clip enforces a trust region so the policy can't drift too far in one update.

(c) Critic update. Clipped value loss (PPO2 style): $V_\theta(S_t)$ regressed against the GAE return target, with an extra clip $V_{\text{old}} \pm \varepsilon$ limiting per-step movement. The return target now genuinely includes bootstrapped future fractions, so the critic learns to predict whole-course return-to-go.

(d) Entropy bonus. Small reward (coef $0.005$) for the policy staying spread out, so the agent keeps exploring beamlet intensities rather than collapsing onto one rigid plan too early.

All of this runs for 6 epochs over the 280-transition batch in mini-batches of 64. Gradients are clipped to L2-norm 0.5 and Adam steps with lr = 1.5e-4. Per-batch NaN-guards re-check every gradient before opt.step() — any non-finite gradient skips that batch.

Checkpoints. Written under runs/:

  • warmstart.pt — saved once after Step 4a, before any PPO update. Lets you evaluate the imitation policy alone.
  • best.pt — saved whenever the validation DVH score sets a new minimum. Every best_eval_every = 25 patients we run deterministic rollouts on the first best_n_val_patients = 6 patients of the eval split and save if the mean DVH score (lower is better) improved. A final validation pass at the end gives the last policy a chance to claim best.pt too. The old rolling-mean-reward rule is kept only as a fallback when no validation patients exist.
  • ep<N>.pt every eval_every = 50 patients, and last.pt at the end so a final checkpoint always exists.

Live diagnostics in the tqdm bar. Each patient prints R (this patient's total reward), Ravg (rolling mean), loar (the curriculum-ramped λ_oar), pi/v (policy & value losses), mu (mean of actor_mu.bias), lstd (mean log_std), and a_mean/a_max (action stats). A frozen policy would show mu stuck at $-1.000$ and a_mean at $\approx 0.31$; after the warm-start those move.

Phase 3 — Evaluation (deterministic, no learning)
Step 11 · evaluate.py — grade the trained agent deterministic=True
runs on cfg.eval_split (validation by default) · pass --split test for the final report

Evaluation runs the same 35-fraction course per patient with two changes:

(1) Deterministic actions. No random sampling; the agent always uses the policy's mean. Reproducible plans (run twice → same plan), essential for a clinical workflow.

(2) No learning. Weights are frozen. We're measuring, not training.

For each patient we compute:

  • MAE — average |predicted − clinical| dose, masked to the possible-dose region
  • DVH score — mean over present structures of |ΔD95| + |ΔDmean| vs ground truth (lower is better; this is also the best.pt selection metric)
  • D95 per PTV (full mask) — coverage of each tumour class. With the DIM downsampler now covering every target voxel, this is the headline coverage metric again.
  • D95r per PTV (reachable-only) — D95 over PTV voxels with at least one non-zero DIM entry. After the downsampler fix this matches the full-mask D95 within rounding (reachability ≥ 99.5 %); kept as a guardrail against future DIM regressions.
  • %reach per PTV — fraction of PTV voxels physically reachable by any beamlet. Currently 99.7–100 % across all 206 patients; was 72–76 % before the downsampler fix.
  • Mean dose per OAR — for each healthy organ

Results print as one aligned table with a final MEAN row, followed by a CONFIG SNAPSHOT block so the exact reward/tolerance settings are saved alongside the metrics. Structures absent for a patient show as - rather than misleading zeros. Pass --charts-patient pt_201 (or first) to also dump per-patient DVH / dose charts.

Which checkpoint? runs/warmstart.pt is the imitation-only policy; runs/best.pt is the best-validation-DVH policy during PPO; runs/last.pt is the final policy. Comparing them shows whether PPO improved on the NNLS warm-start.

Phase 4 — Web UI (Flask backend serving a browser front-end)

app.py is a small Flask backend that wraps the same DoseEnv + PPO stack behind an HTTP API a browser can call.
